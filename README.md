# 公众号自动发布工作流

> 把公众号文章从写稿一路送到草稿箱，最后一步群发留给人。核心问题不是「能不能 automate」，而是「自动化的边界画在哪里」。

详细复盘见博客文章：[公众号自动发布：把稿子送到草稿箱，最后一步留给人](https://koujiaohan.github.io/posts/gzh-auto-publish.html)。

## 公众号 vs 知乎：自动化边界不同

| 维度 | 公众号 | 知乎 |
|---|---|---|
| 发布通道 | 有官方 API（发草稿箱） | 无官方发布 API（个人号） |
| agent 能做 | 写稿 + 去味 + 发草稿箱 | 只能出「内容三件套」给人复制 |
| 最后一步 | 人点群发 | 人手动登录后台发 |

## 标准五步

| 步骤 | 谁做 | 做什么 |
|---|---|---|
| 1 写稿 | agent | 从真实素材库挖事件，按调性写，不杜撰数字 |
| 2 去味质检 | agent | 过 humanizer + 排版规范 |
| 3 dry-run 校验 | agent | 跑双关卡，ERROR 清零才准发 |
| 4 发草稿箱 | agent | 走官方 API，真发到草稿箱 |
| 5 群发 | **人** | 后台人工点，agent 绝不代点 |

## 关键设计

### dry-run 双关卡
真发之前先跑 `gzh_publish.py 文章.md --dry-run`：只生成润色 HTML + 双关卡检查（标点、禁用表述、结构），ERROR 清零才允许 `--apply`。

```
# 预览校验
python gzh_publish.py "文章.md" --dry-run
# ERROR 清零后真发草稿箱
python gzh_publish.py "文章.md" --apply
# 自定义封面
python gzh_publish.py "文章.md" --apply --cover "封面.png"
```

本质是把不可逆操作拆成「可预览 + 可确认」两步。

### 人工闸门
「花销 / 群发 / 删库 / 改手写文档」四类动作一律留给人拍板。群发不可逆、一次面向全部订阅者，这类地方就该有个人决定。

### 写稿：真实 > 漂亮
写稿必须从真实事件库取材，口头禅原样保留，数字不杜撰。AI 写内容最大的风险不是写得差，而是写得像那么回事却是编的。「去味」去掉的是 AI 腔，不是真人味。

## 方法论要点

1. **在生效前先看可核验的中间态**：dry-run 是这个原则的具体落地
2. **边界画对了，自动化才敢放心用**：能自动的都自动，不可逆的留人
3. **去 AI 腔但留真人味**：真实素材是底线
